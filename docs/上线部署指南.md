# 上线部署指南 · 织流 AgentWeave

> 适用版本：v1.1（生产化加固后）｜Python 3.10+，零第三方依赖
> 目标：从「本机演示」平滑升级为「内网/公网可长期运行」的服务。

---

## 一、部署前必读（5 分钟）

AgentWeave 是**单进程 + 单机**架构：HTTP 服务、调度器、Agent 执行器、事件总线在同一进程内。
这适合中小规模（单机并发运行 ≤ 4、节点并发 ≤ 4）。若需要多机 worker 池、消息队列或数据库，
请在此基础上替换 `RunStore` / `Scheduler` 后端（见 `docs/CONTRACTS.md`），本文档不覆盖分布式改造。

| 项目 | 最低要求 | 说明 |
|---|---|---|
| CPU / 内存 | 2C / 4GB | 演示与内网使用；真实模型调用主要受网络与配额约束 |
| Python | 3.10+ | 纯标准库，无 `pip install` |
| 磁盘 | 1GB 起 | `data/runs/` 默认保留最近 50 次运行（可配置） |
| 网络 | 出站可访问 LLM 端点 | 使用离线 Mock 时完全断网可运行 |
| GPU / Docker / 数据库 | **不需要** | 默认无外部依赖 |

## 二、快速上线（Docker，推荐）

```bash
# 1) 构建（在仓库根目录）
docker build -t agentweave:1.1 .

# 2) 运行（数据与日志挂载到宿主机）
docker run -d --name agentweave \
  -p 8765:8765 \
  -e AGENTWEAVE_AUTH_TOKEN="请替换为32位以上随机串" \
  -e AGENTWEAVE_API_KEY="sk-xxx" \
  -v $(pwd)/data:/app/data \
  --restart unless-stopped \
  agentweave:1.1

# 3) 健康检查
curl http://127.0.0.1:8765/api/health
```

浏览器打开 `http://<服务器IP>:8765`。启用鉴权后，管理写操作需在 URL 上带一次 token：

```
http://<服务器IP>:8765/?token=<AGENTWEAVE_AUTH_TOKEN>
```

前端会把 token 存进 localStorage，后续写请求自动携带 `Authorization: Bearer <token>`。

## 三、无 Docker 部署

### 3.1 Linux（systemd）

```ini
# /etc/systemd/system/agentweave.service
[Unit]
Description=AgentWeave multi-agent orchestration platform
After=network.target

[Service]
Type=simple
User=agentweave
WorkingDirectory=/opt/agentweave
Environment=PYTHONIOENCODING=utf-8
Environment=AGENTWEAVE_AUTH_TOKEN=请替换为32位以上随机串
ExecStart=/usr/bin/python3 /opt/agentweave/server.py --host 0.0.0.0 --port 8765
Restart=on-failure
RestartSec=3

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now agentweave
sudo systemctl status agentweave
journalctl -u agentweave -f
```

### 3.2 Windows（计划任务 / NSSM）

```powershell
# 方案 A：计划任务（开机启动，无控制台窗口）
schtasks /Create /TN "AgentWeave" /TR "py -3.14 D:\agentweave\server.py --host 0.0.0.0 --port 8765" /SC ONSTART /RU SYSTEM /RL HIGHEST

# 方案 B：NSSM 注册为服务（推荐，可自动重启）
nssm install AgentWeave "py" "-3.14 D:\agentweave\server.py --host 0.0.0.0 --port 8765"
nssm set AgentWeave AppDirectory D:\agentweave
nssm start AgentWeave
```

## 四、生产配置（config/platform.json）

```json
{
  "server": { "host": "0.0.0.0", "port": 8765, "auth_token": "" },
  "limits": { "run_per_minute": 10, "post_per_minute": 60 },
  "logging": {
    "level": "INFO",
    "file": "data/logs/agentweave.log",
    "max_bytes": 5000000,
    "backup_count": 3
  },
  "runtime": { "max_concurrent_runs": 4, "run_history_keep": 50 },
  "llm": { "provider": "openai", "base_url": "https://api.deepseek.com/v1", "model": "deepseek-chat" }
}
```

| 配置 | 作用 | 建议 |
|---|---|---|
| `server.auth_token` / 环境变量 `AGENTWEAVE_AUTH_TOKEN` | Bearer 鉴权（仅保护写接口） | 生产必填；用 32 位以上随机串；优先放环境变量 |
| `limits.run_per_minute` | 每 IP 每分钟触发运行上限 | 10；公开演示可降到 3 |
| `limits.post_per_minute` | 每 IP 每分钟其它写请求上限 | 60 |
| `runtime.max_concurrent_runs` | 同时运行的 run 数上限（超出返回 429） | 按 CPU/内存设 2–8 |
| `runtime.run_history_keep` | `data/runs/` 保留最近 N 次 | 50；磁盘大可以调高 |
| `logging.file` | 轮转日志文件 | 必须配置，便于排障 |
| `llm.api_key_env` | LLM Key 的环境变量名 | 默认 `AGENTWEAVE_API_KEY`；Key 不写进仓库 |

> `.env` 支持的键：`AGENTWEAVE_PROVIDER` / `AGENTWEAVE_BASE_URL` / `AGENTWEAVE_MODEL` / `AGENTWEAVE_API_KEY`；
> 优先级「真实环境变量 > 仓库根 `.env` > `config/platform.json`」，`.env` 已在 `.gitignore` 中。

> 安全说明：鉴权只覆盖 `POST`（改配置、触发运行、保存工作流）。`GET` 读接口默认开放，
> 便于只读展示与 SSE；公网部署请在反向代理层再加一层登录（如 Nginx Basic Auth / OAuth2 Proxy）。

## 五、Nginx + HTTPS（公网推荐）

```nginx
server {
    listen 443 ssl http2;
    server_name agent.example.com;

    ssl_certificate     /etc/letsencrypt/live/agent.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/agent.example.com/privkey.pem;

    client_max_body_size 3m;

    location / {
        proxy_pass http://127.0.0.1:8765;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;

        # SSE：必须关闭缓冲，否则事件流会攒批
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 3600s;
    }
}

server {
    listen 80;
    server_name agent.example.com;
    return 301 https://$host$request_uri;
}
```

上线后验证：

```bash
curl -s https://agent.example.com/api/health | head -c 300
curl -s https://agent.example.com/api/metrics | head -c 500
curl -N https://agent.example.com/api/runs/<run_id>/events | head -5   # 应逐条输出 data:
```

## 六、可观测性

| 端点 | 用途 |
|---|---|
| `GET /api/health` | 存活/版本/LLM/Agent/调度器状态，可接 K8s liveness |
| `GET /api/metrics` | 请求量、错误、401/429、运行状态分布、Token 合计、平台快照 |
| `data/logs/agentweave.log` | 轮转文件日志（含 access 行：方法/路径/耗时） |
| `data/runs/<run_id>/` | 每次运行的可审计产物：report.md / metrics.json / events.jsonl / summary.json |

告警建议：
- `/api/health` 5xx 或超时 → 实例异常；
- `/api/metrics` 的 `runs.by_status.failed` 持续增长 → 模型或数据问题；
- 日志中 `rate_limited`/`unauthorized` 突增 → 被刷或 token 泄漏。

## 七、备份、升级与回滚

```bash
# 备份（运行历史 + 配置）
tar czf agentweave-backup-$(date +%F).tgz config/ data/runs/ data/logs/

# 升级
git pull --ff-only
py -3.14 -m unittest discover -s tests -t .   # 先跑测试
sudo systemctl restart agentweave

# 回滚
git checkout <上一个提交>
sudo systemctl restart agentweave
```

`data/runs/` 是纯文件产物，删除旧目录不影响服务；配置变更后重启生效。

## 八、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 启动报端口占用 | 旧实例未退出 | `netstat -ano \| findstr :8765` → 结束 PID，或 `--port` 换端口 |
| 页面能开但数据 401 | 已启用鉴权 | URL 加 `?token=...`，或写请求带 `Authorization: Bearer` |
| 触发运行返回 429 | 触发限流/并发达上限 | 降低频率；或调大 `limits` / `max_concurrent_runs` |
| SSE 不实时 | 反向代理缓冲 | Nginx 加 `proxy_buffering off;` |
| 重启后历史运行没了 | 旧版本只在内存保存 | v1.1 起写 `summary.json`，列表/详情会自动读磁盘 |
| 日志文件过大 | 未启用轮转 | 配置 `logging.file` + `max_bytes`/`backup_count` |

## 九、上线检查清单

见 [`生产化检查表.md`](生产化检查表.md)。核心 5 条：

1. `AGENTWEAVE_AUTH_TOKEN` 已设置且未写入仓库；
2. Nginx/负载均衡层已启用 HTTPS；
3. `/api/health` 与 `/api/metrics` 已接入监控；
4. `data/logs/` 有轮转日志且磁盘有余量；
5. 已实际跑通一次「触发运行 → 验证通过 → 报告落盘」。
